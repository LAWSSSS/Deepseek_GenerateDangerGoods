# 在线薄雾、池化与浮灰测试

本轮把已测试的三种效果接到 HTTP、网页和批量执行器。请求不含 `effects` 时保持旧流程。显式提供 `effects` 后使用局部低饱和摄影，默认 3×3 均匀池化、35% **追加**薄雾和 0.5 倍表面浮灰。全图平均只用于照明标量，雾色与相机参数继续从落点邻域估计。

## 网页与接口

按根目录 README 启动本机网页后，打开 `/batch`，将“运行方式”改为“在线效果小样”。每批最多 15 项，初稿后默认最多两轮修正，可以设为 0–10。页面报告使用完整监控画面，点击可打开原尺寸 PNG。

2026-11-12 新增[统一尺度与局部雾化试验](DISPLAY_LOCAL_ADAPTATION.md)。网页小样可选择 `physical_consistent`、`preserve_source`、`local_auto`；旧 API 请求省略这些字段时继续使用下述旧语义。新做旧模式的浮灰上限为 0.5，零浮灰恢复原材质；自动雾模式计算总雾量，忽略追加雾值。普通批量默认未切换。

- `GET /api/batches/effects` 返回默认值、参数限制、允许的 AI 动作和各动作重算范围。
- `POST /api/batches/test` 创建在线小样，未指定任务数时默认 1 项，必须启用在线复核。
- `POST /api/batches` 也接受 `effects`，保留原有批次任务上限。
- `GET /api/batches/{id}` 返回进度、效果配置和实际累计请求/token/费用估算。
- `POST /api/batches/{id}/resume` 从中断处继续，配置不变。
- `GET /api/batches/{id}/files/index.html` 查看完整画面，`results.jsonl` 查看逐项证据与修改历史。

示例请求体如下。背景目录替换为本机实际目录，不在请求中填写密钥。

```json
{
  "backgrounds": "C:/Users/zhaoc/Desktop/背景图",
  "assets": ["3", "13"],
  "count": 2,
  "max_iterations": 2,
  "effects": {
    "fog_extra": 0.35,
    "pool_kernel": 3,
    "surface_dust": 0.5,
    "ai_adjust": true
  }
}
```

请求成功返回 202、批次编号、保存目录、状态地址和报告地址。参数错误返回 400，不启动渲染。视觉服务鉴权或全局服务错误暂停批次，保留待审草稿和账本。使用既有服务配置与本机环境凭据，服务选择沿用 `provider_config`，不改变凭据来源。

命令行与接口使用同一执行器，可复制 [配置示例](../../tools/ps-model-controller/display-effects.example.json)，设置输出到新目录后运行。

```powershell
& work/triposr-env/Scripts/python.exe -X utf8 -B tools/ps-model-controller/batch_display.py run --config tools/ps-model-controller/display-effects.example.json
```

## 参数和独立性

| 参数 | 允许范围 | 行为 |
|---|---|---|
| `fog_extra` | 0–0.85 | 追加空气遮蔽权重，默认 0.35。实际总量包含已有局部雾量，上限 0.90。局部证据不足或清晰区域不强行加雾。 |
| `pool_kernel` | 整数 1–64 | 最终投影像素上的方格均值池化。1 关闭。边缘采样不足时不执行。 |
| `pool_weight` | 0–1 | 池化结果混入比例，默认 1。 |
| `surface_dust` | 0–1 | 三维表面浮灰覆盖倍率，默认 0.5。漆面再乘既有 0.5 系数，塑料不加额外层。 |
| `lighting` | `global_mean` / `local` | 默认沿用已点评的全图平均取光，也可显式选择扩大邻域均值取光。 |
| `ai_adjust` | 布尔值 | 是否允许 AI 修改以上薄雾、池化格和浮灰倍率。设为 false 固定三项，其他既有修正仍可执行。 |

`atmosphere: off` 同时关闭基础及追加薄雾。关闭浮灰覆盖不取消已确认的漆面哑光设置。任何效果只修改可见物品 RGB，保留透明孔洞、接触锚点、前景遮挡与保护区。阴影继续来自渲染接收面。

薄雾、池化变化只重合成和复核。浮灰变化重渲物体与有物体阴影，无物体阴影缓存继续复用。基础姿态不重新落稳。记录请求值和实际生效值，证据不足导致未生效时不再向 AI 提供对应动作。

## 在线模型的受限动作

视觉请求提供最终全景、局部邻域、模型参照、当前参数、实际生效测量及允许动作。模型返回原七项评分、插入痕迹判断、可见缺陷与最多三项动作。每轮只执行同一原因且同一计算阶段的动作。

| 缺陷 | 对应动作 | 方向 |
|---|---|---|
| `haze_clear` / `haze_heavy` | `fog_extra` | 增加 / 减少空气薄雾 |
| `too_sharp` / `too_blurry` | `pool_kernel` | 增大 / 减小池化格 |
| `surface_clean` / `surface_dust_heavy` | `surface_dust` | 增加 / 减少表面浮灰 |

动作格式示例为 `{"kind":"surface_dust","value":"0.25"}`。值必须使用本轮提供的字符串选项。程序拒绝越界、反方向、无对应可见缺陷、重复或未提供的动作。旧的 `dust/haze/sharpness` 档位在效果模式中不同时开放，防止对同一效果叠加调整。参数和成图重复时停止，不继续付费复核。纯塑料不提供浮灰动作。

修改后复核真实新 PNG，旧分数不能迁移。程序失败不能被 AI 分数覆盖，物理证据未知仍保持 `review`。只有初稿复核，没有有效动作时也会正常结束。

接口与动作回归见 `checks_display_effects.py`，包含参数边界、反向动作、无效动作、塑料隔离、透明孔洞、渲染依赖和在线请求输入。批量回归 148 项、网页检查 36 项通过，前端脚本语法检查通过。以上接口模拟和循环模拟不构成视觉验收。
